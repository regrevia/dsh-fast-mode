# 长任务基准 fixture 合同

目标：让一个真实的编码 agent 需要 10–25 个工具步才能完成；用隐藏测试客观打分。

## 目录（一个 fixture 一个目录）

```
bench/suite/<id>/
  PROMPT.txt         # 交给 agent 的任务描述（中文或英文皆可，英文更稳）
  hidden/test_<id>.py   # 隐藏测试（unittest，agent 看不到）
  ref/<entrypoint>   # 参考实现，必须 100% 通过隐藏测试
  meta.json          # {"id":..,"entrypoint":"ledger.py","testCmd":"python3 -m unittest test_<id>","minSteps":10,"maxSteps":25}
```

## PROMPT.txt 硬要求

1. 任务在**空目录**里可解，只用标准库 / 系统自带命令，不联网，不装包。
2. 明确写出交付物路径（agent 的工作目录就是空的 run 目录，直接写相对路径）。
3. 明确写出**最终回答必须恰好是**一行标记，例如 `ledger.py ready`，便于 runner 判定结束。
4. 不得透露隐藏测试的内容或数量；但规格必须完整到只有一个合理解（边界要写清：排序、并列、精度、空输入、坏输入）。
5. 不许要求提问、不许要求人工确认；不许依赖当前日期、随机数（除非固定种子）、locale。
6. 规模控制在 10–25 步：至少 4 个可独立验证的功能点或 6 个边界条件，必须有“想清楚才能写对”的规格细节，但不要堆到 40 步。

## hidden/test_<id>.py 硬要求

1. 只用 `unittest` + 标准库；`python3 -m unittest test_<id>` 直接可跑（测试放在 run 目录根下，由 runner 复制）。
2. ≥ 12 条断言/≥ 8 个 test 方法，覆盖：正常路径、每个边界、错误输入（异常类型与消息关键字）。
3. 表达式精确（字符串逐字符、`Decimal` 精确比较、排序结果全等），不要用模糊匹配。
4. 运行时间 < 5 秒，无网络、无 sleep、无临时文件残留。
5. 对参考实现必须全绿；对“少实现一个函数 / 少一个边界”的残缺实现必须红（作者要亲手验证这一点，见下）。

## ref/<entrypoint> 硬要求

1. 放在 `ref/` 下，能被原样复制到 run 目录通过全部隐藏测试。
2. 风格不重要，正确性重要；不许 import 隐藏测试。

## 作者必须自证（把命令输出贴在交活说明里）

```bash
cd bench/suite/<id>
d=$(mktemp -d) && cp -r ref/. "$d"/ && cp hidden/test_<id>.py "$d"/ && (cd "$d" && python3 -m unittest test_<id> 2>&1 | tail -3)
# 再证明它确实能红：把参考实现里一个边界改坏，重跑，必须出现 FAILED
```

两条都要贴输出。若参考实现不能全绿，改测试或改参考实现，直到全绿；若改坏边界后仍然全绿，说明测试太弱，必须加强。

## 任务难度标定（重要）

写完后用一句话说明：**一个熟练工程师要几步才能完成**（读规格 1 步、写文件 2–3 步、写测试/试跑 2–4 步、修错 2–6 步）。如果估出来 < 8 步，任务太简单，加一个需要推理的边界（例如并列规则、进位、幂等性、增量更新、错误恢复）；如果 > 25 步，删掉一个功能点。
