# 量 fast mode：配对 A/B 的玩法

工具在 `audit/run.mjs`，方法说明在 `docs/AUDIT.md`。这份文件是操作顺序和说话尺度。

## 什么时候用

- "fast mode 对我有用吗 / 能快多少 / 值得开吗"——要数字，不是要形容词。
- 有人拿来一个提升数字（"快了 30%"），要判断它是不是噪声。
- 改过提示词策略之后要回归，看有没有把某个场景弄慢。

不该用：只想知道它改了什么的（读 `docs/REFERENCE.md`）；没有凭据、跑不起真调用的时候——
那时先说明，别硬编数字。

## 准备任务清单

从**这个人真实在干的事**里挑 3–6 个只读任务，写成 JSONL，一行一个：

    {"id": "read-package", "prompt": "读 package.json，说出 scripts 里有哪些命令", "check": "test -f package.json"}
    {"id": "grep-geomean", "prompt": "在 src/ 里找几何均值或对数平均相关的实现，指出文件和行号", "check": "test -d src"}

`check` 是这次调用之后跑的一条 shell 命令，退出码 0 算通过。它只守两件事：这次调用真的跑完了、
仓库没被写坏。它**不给答案打分**——答得好不好不在这份工量具的判据里，别用它暗示质量结论。

挑任务的规则：

- 只读。会改文件的任务每个臂都在改，第二轮开始比的就不是同一件事了。
- 覆盖不同形状：一个纯 IO（列文件）、一个读文件、一个搜索、一个跑测试、一个解释代码。样例见
  `audit/tasks.example.jsonl`。
- 提示词写成本人会那么说的样子，别为了好看而重写——优化过的提示词测的是优化后的场景。
- 别把 5 个几乎一样的任务塞进去凑数，重复的任务只会让区间变窄而不会让结论更真。

## 跑

先展开命令行看一眼（什么都不执行）：

    node audit/run.mjs --dry-run --cwd <仓库> --tasks <清单>

确认三件事：`--profile` 是你装了 fast-mode 的那个（默认 `bench`）、两臂的 patch 一个
`enabled: false` 一个 `enabled: true`、任务原文在最后且没被 shell 拆开。然后真跑：

    node audit/run.mjs --cwd <仓库> --tasks <清单> --rounds 3

**串行跑，别并行。** 两臂抢 CPU 和模型并发额度，测出来的就是调度差异。跑起来之后就是等，
每个任务 3 轮 × 2 臂，5 个任务大约 30 次调用。

## 读报告

`audit-out/<时间戳>/report.md` 里每行一个结论：

- 看**区间**，不看中心值。
- 区间整体 < 1：变快，报告里的百分比是省下来的比例。
- 区间整体 > 1：变慢，直接说变慢，别找理由圆过去。
- 跨 1，或中心值离 1 只有几个百分点：写"无法区分"。本机噪声常在 5% 上下，这不算失败，算诚实。
- 配对 < 6：报告自己会写"样本不足，不做结论"，原样转述，别替它下判断。

`pairs.jsonl` 是原始读数，有人质疑时把对应的行贴出来。

## 该说"你的场景没有加速"的时候

这些情况都直接说，不用铺垫：

- 任务大头是工具执行（跑测试、装依赖、读大文件），模型本来就没说多少话。
- 输出本来就短，或者任务必须产出完整长内容。
- 想先看看噪声有多大：`--arm-style none` 两臂同命令跑一遍，那个区间宽度就是这台机器的底噪；
  "加速"要是和它差不多宽，那就是噪声。
- 有任务每次检查都不通过：那是失败重试，不是快慢。

## 出错时

- `MISSING_CREDENTIAL` / provider 报错：说明这台机器/这个 shell 没凭据，真调用跑不了。此时
  不能给任何耗时结论，只能说命令行和结构已验证。
- profile 探测失败（`managed exclusively by the Electron application`）或里面没有 fast-mode：
  换 profile，工具会停下并告诉你该看哪里。不要用 `--arm-style insert` 硬插——那会在已经有该条目
  的 profile 里造出两条，两臂可能落在同一个开关上，报告看起来却是"接近 1.0 的正常结果"。
- 升级 dsh 或换机器后默认路径可能失效：`--dsh-bin` 指到新的 launcher，先用 `--dry-run` 确认。

## 别做的事

- 不并行跑，不在跑到一半改清单或轮数。
- 不拿估算当测量：没有 token 数据就是 `N/A`，不按字数折算。
- 不同轮次之间不手动改 prompt、不改模型、不改推理档位——fast mode 本身也不碰这些，两边都别碰，
  否则比的不是同一个东西。
- 不把"比值 0.98"说成"快 2%"。低于噪声的差值就叫无法区分。
